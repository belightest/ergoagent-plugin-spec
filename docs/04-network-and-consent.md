# 04 · 网络申报与安装同意

## 为什么强制 `network.domains`

静态分析抓不到运行时动态拼接的 URL，也抓不到藏在依赖 SDK 里的外联。**申报制让外联目的地对人可见**——这是 T1 插件“表面查天气、实际外传数据”这类风险的主要对冲手段（参考 Dify 的同名机制）。

规则：

1. 凡 manifest 含 `network:<domain>` 能力，`network.domains` 必填，精确域名或 `*.` 前缀通配
2. 代码中出现的域名 ⊆ 申报范围；超出即阻断
3. 运行时实际访问未申报域名 → 该次请求被拒并记录事件（按 05 处理）
4. `PRIVACY.md` 必须写明：收集什么、存在哪、发给谁；**不收集也要明示**

## 安装时的权限明示（用户同意）

安装弹窗按 manifest 原样展示，不美化、不折叠：

```text
⚠️ 此插件由第三方开发

插件：天气查询 1.2.0（签名：a1b2c3d4…）
需要以下能力：
  · 访问网络：api.weather.com, *.tile.openweathermap.org
  · 只读你的工作区文件
风险评级：A（扫描完成，无高危发现）

源码可审计：https://github.com/example/ergoagent-weather（建议安装前查看）
隐私政策：…/PRIVACY.md

[ 取消 ]  [ 了解风险并安装 ]
```

- **评级 C 或未申报敏感外联**：红字警告 + 二次确认
- **T2 能力**：第三方插件不展示安装入口（v1 未开放）
- 安装即同意：本次明示的能力范围 + 评级快照写入本地安装记录，用户可随时查看“已安装插件各要了什么”

## 运行时一次性授权

插件**首次真正行使**某项 T1 能力时，应用内弹一次性确认：

```text
「天气查询」正在请求：读取你的工作区文件
仅此一次 / 本次会话内允许 / 始终允许 / 拒绝
```

与核心智能体的逐项审批同一套交互；用户选择“始终允许”后可在设置中撤回。

## 数据边界承诺（规范层面）

- 插件不得将用户数据发送至申报域名之外的任何目的地
- 插件不得缓存、转存用户数据到本地申报之外的持久化位置
- 违反以上两条 = 确认恶意，直接走 05 的吊销流程，不进入分级争议
