# 05 · 滥用处理与吊销

## 渠道与时限

| 事件 | 渠道 | 响应 |
|---|---|---|
| 漏洞/恶意行为报告 | 注册仓库 Security 私密渠道（Private Vulnerability Reporting） | 72 小时内确认 |
| 一般争议/侵权 | 注册仓库公开 Issue | 7 天内评估 |
| 确认恶意或严重安全问题 | — | **直接限制分发/下架/人工复核，跳过常规评级** |

响应速度优先于评审深度。GlassWorm 类供应链事件（经 OpenVSX/VS Code 感染 35,800 安装）的教训：**早期检测 + 快速下架**比事前审得细更能限制爆炸半径；仿冒插件 4 小时内下架时仅 6 次下载——这就是想要的结果。

## 处置梯度

| 级别 | 情形 | 动作 |
|---|---|---|
| L1 警告 | 申报不全、依赖陈旧、README 缺失 | 限期修复；逾期限制新安装 |
| L2 限制 | 中危发现、外联超出申报、维护失联 | 暂停新安装/新版本；通知作者 |
| L3 下架 | 高危漏洞、故意低报风险等级、静默增加能力 | 全部版本下架；扫描报告公开 |
| L4 吊销 | 确认恶意：外传用户数据、凭证窃取、欺骗审核 | **吊销签名指纹**；全部版本下架；公开事件摘要；指纹列入黑名单 |

## 吊销的技术效果

1. 签名指纹进入吊销列表，随客户端分发
2. 已安装用户下次启动收到明确通知（“插件 X 因恶意行为被下架并禁用”）
3. 该指纹名下的任何新提交直接阻断
4. 作者可凭身份证明申诉，误判可恢复——但**确认恶意的外传行为不设恢复**

## 事件手册（确认恶意后）

1. **止血**：下架 + 吊销 + 推送吊销列表（分钟级）
2. **定界**：扫描报告 + 版本级时间线，确定受影响版本与安装面
3. **通知**：注册仓库 Security Advisory + 已安装用户应用内通知
4. **复盘**：公开事件摘要（时间线、入口、缺口、修补），更新门禁规则

## 版本级验证原则

- 评分、签名、扫描报告都绑定**具体版本**；旧版本结论不继承给新代码
- 升级必须重签 + 重扫 + 重评级；任何一环缺失 = 阻断
- 注册仓库保留全部历史版本包体，支持回溯取证
