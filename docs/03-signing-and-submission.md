# 03 · 签名与上架流程

## 签名（强制）

- 每位插件作者持有自己的密钥对；**私钥自留，公钥指纹写入 manifest `author.signing_key`**
- 提交流程：打包 → 本地校验 → 私钥签名 → 提交 `.ergoplugin` + `.sig`
- 客户端安装时验证签名；**未签名或签名不匹配 = 默认禁止安装**（与 Dify 的签名策略一致）
- 签名即追责锚点：滥用属实 → 吊销该签名指纹，全部关联版本下架

## 提交流程（PR 制，透明可审计）

插件注册仓库（`ergoagent-plugins`）接受 PR，每个 PR 只提交一个插件的一个版本：

```text
<author-namespace>/<plugin-id>/<plugin-id>-<version>.ergoplugin
```

PR 模板必须包含（与 manifest 一致，缺一即阻断）：

1. 作者、插件、版本、**公开源码仓库**、可维护的联系渠道
2. 风险等级自声明（low / medium / high，就高）
3. 安全与隐私说明：命令/代码执行、SQL、SSH、文件操作、任意 URL 获取、敏感数据处理——均不适用填 None
4. 本地校验命令与结果（禁止只写“已测试”）

## 机器门禁（`ergoagent-plugin-toolkit validate`，全量自动）

作者本地先跑，CI 复核。**阻断错误（blocking）**不过即拒；**警告（warning）**转人工判断：

| 检查项 | 级别 |
|---|---|
| 包体卫生：安全解压、无 `.git/`/venv/缓存/日志/`.env`/密钥模式/可疑二进制 | blocking |
| manifest 完整性：id/version/source/contact/privacy/risk_level 必填且与 PR 描述一致 | blocking |
| 依赖审查：依赖树 OSV 已知漏洞扫描；禁止裸需求、直 URL 安装、git 依赖（PR 说明理由除外） | blocking（高危漏洞）/ warning（中低危） |
| 代码编译与安全模式：语法编译、`eval`/动态执行/外联/路径穿越等危险模式 | blocking |
| **出站域名核对**：代码中出现的域名 ⊆ `network.domains` 申报范围 | blocking |
| 隐私政策存在且覆盖：收集/存储/发送范围 | blocking |
| README 质量：用途、凭证要求、安装步骤、源码链接 | warning |
| T1 能力与申报一致性（workspace:read / upload.process 与实际调用核对） | warning |
| 签名有效性与指纹匹配 | blocking |

> 自动化 augment 审核者，但全绿不等于有判断力。阻断线之上是闸门，线以下是给人看的上下文。

## 人工审核的三种例外（且仅三种）

1. **T1 一键确认**：机器门禁全过的 T1 插件，进维护者确认队列，通过即上架
2. **警告申诉**：作者对 warning 有合理解释时，人工裁量
3. **抽样巡检**：已上架插件按 10% 抽样复查

T0 无人审；T2 不开放。

## 安全评级（每版本独立）

| 评级 | 含义 |
|---|---|
| **S** | 完整扫描、无高危/中危发现；依赖、权限、域名信息完整；作者信号已验证 |
| **A** | 扫描完成、无高危；依赖与域名信息基本完整 |
| **B** | 需注意：依赖陈旧、中低危发现、作者未验证、扫描或域名透明度不全 |
| **C** | 明确风险：高危漏洞、异常权限、未申报的敏感外联、可疑历史——**安装前红字警告** |
| **Unscanned** | 未完成扫描/证据不足 |

评级跟随**当前版本**，升级必须重扫；评级徽章在安装前可见（见 04）。

## 官方市场与早期分发

v1 阶段不建官方市场：分发 = 注册仓库 + 客户端 `plugin add <id>`（参考 DeepSeek Harness 早期路径）。官方市场（应用内搜索/一键安装/自动更新）在生态稳定后启用，门禁规则不变。
