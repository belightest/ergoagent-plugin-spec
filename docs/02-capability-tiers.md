# 02 · 能力分级（T0 / T1 / T2）

**能力即威胁面。** manifest 没声明就没有该能力；分级决定审核深度与陌生人可发布范围。

## 三级定义

| 级别 | 定义 | 陌生人可发布 | 审核 |
|---|---|---|---|
| **T0 纯功能** | 无网络、无文件系统、无执行。提示词模板、数据转换、导出格式、UI 主题、纯计算工具 | ✅ 开放 | **纯机器**：schema 校验 + 静态扫描 + 签名 + 源码链接有效性。不过即拒，无人工环节 |
| **T1 受限** | 只读工作区文件；访问 `network.domains` 申报内的域名；处理用户主动上传的内容 | ✅ 开放 | 机器全量审 + **维护者一键确认**（预计量极小） |
| **T2 高危** | 写文件、执行命令、运行 SQL、SSH/SFTP、浏览器自动化、代理/爬取任意 URL、捆绑可执行文件、处理高敏个人数据 | ❌ **v1 不开放**（仅官方插件） | 不适用 |

T0 按构造无法威胁核心与其他客户端——没有能力可被滥用。这就是“机器审完直接上架”在安全上成立的原因。

## 能力白名单（v1）

```text
纯计算/模板类（T0，无需声明外能力）:
  prompt.template        提示词模板
  data.transform         数据格式转换
  ui.theme               UI 主题
  export.format          导出格式

受限类（T1，须显式声明）:
  network:<domain>       访问指定域名（域名须同时出现在 network.domains）
  workspace:read         只读工作区文件
  upload.process         处理用户主动上传的文件内容

高危类（T2，第三方关闭，仅官方）:
  workspace:write        写工作区
  process.exec           执行命令
  sql.query              数据库查询
  ssh,sftp               SSH/SFTP
  browser.automate       浏览器自动化
  network:proxy          代理/爬取任意 URL
  sensitive.pii          处理高敏个人数据
```

## 运行时强制（审核之外的兜底）

1. **白名单注入**：客户端只注入 manifest 声明过的能力；未声明 = 运行时不存在
2. **能力档位**：只读/可写档位沿用核心智能体模型；插件调用危险能力时走**逐项审批**（与现有架构一致）
3. **工作区边界**：路径越界（`../`、绝对路径逃逸）一律拒绝
4. **预算熔断**：插件消耗计入用户预算，超限即停
5. **首次行使确认**：插件第一次真正使用某项 T1 能力时，应用内弹一次性确认（此后可按设置记住）

**分级的含义**：审核决定“谁能上架”，运行时决定“上架后能干什么”。即使漏审，爆炸半径已被上述机制限死。

## 升级与重新评定

- 任何版本升级 = 重新走完整门禁 + 重新扫描 + **重新定级**；旧评分不随版本惯性继承
- 新增能力声明 = 按新等级走审核；**静默增加能力 = 永久下架 + 吊销签名**
